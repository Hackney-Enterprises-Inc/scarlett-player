## What was verified and holds

- **Core auto-init.** `ensureInitialized()` is shared by `init()` and `load()`, re-entrancy-safe through one shared in-flight promise, and cleared on settle so a later `registerPlugin()` is picked up. Lifecycle listeners are wired exactly once behind a flag (double wiring would load every requested source twice), `player:ready` is emitted once at the end of the first pass, the `loadGeneration` supersede guards are preserved around the new await, and `destroyed` is checked inside the init loop. The old dead-event test is replaced, the `once()` docblock now shows subscribe-then-init ordering, and `docs/plugin-authoring.md` correctly states that a plugin subscribing inside its own `init()` does receive the event (plugins initialise before the emit).
- **Poster plumbing.** `setPoster()` / `get poster()` write and read the `poster` state key; both providers subscribe to it and re-apply on element creation, at the top of `loadSource()`, and on every state change; an empty value clears the attribute so a track without art cannot inherit the previous one's; the native provider keeps the attribute off audio sources through a remembered `is_audio_source` flag; the playlist plugin now writes `track.artwork || ''` unconditionally, the same #45-class leak fix titles got; `load()` deliberately leaves `poster` alone and the docblock carries the reason.
- **`ended` key fix.** Both providers mirror `video.ended` onto the key from `play`, `playing` and `seeking`, asking the element rather than assuming, so a seek that lands on the end stays true and setting it true remains the `ended` handler's job. `BigPlayButton.hasEnded()` reads the element with the state key as pre-element fallback.
- **Big play button.** Real `<button>` (type, aria-label, focus-visible), hidden while loading / errored / overlay-up / playing, Replay glyph after `ended`, `hasStarted` latch on first `playing`. z-index 12 sits above the gestures tap surface (6) and below the spinner (15) and error overlay (25), and the visible class uses `visibility`, so it takes no pointer events while away. `setHTML`/`setAttr` diff internally, so the per-update writes do not rebuild the icon or swallow clicks. Reduced-motion overrides included.
- **Embed build.** The native provider is registered in all three builds (`.mp3` / `.mp4` `data-src` no longer answers `PROVIDER_NOT_FOUND`); provider order is hls first, which is load-bearing and safe because the native extension list has no `m3u8` entry (verified); the audio build runs on `hls.js/light` with the ID3 tradeoff documented; chunk names are stable, prefixed per build except the two hls chunks, whose sharing is safe while full and video emit byte-identical `hls.js` (see improvement 3); `emptyOutDir: false` + `rimraf dist tsconfig.tsbuildinfo` + `emitDeclarationOnly` restore the declarations; `exports` list `types` first in embed, core and vue.
- **Version injection.** Every descriptor and every analytics beacon version now comes from `src/version.ts` with `__PKG_VERSION__` wired into each vite/tsup config; the vitest fallback `0.0.0-dev` is semver-shaped and the tests assert shape, never literals; a test pins the light and full hls descriptors to the same version, guarding the shared-factory rule.
- **Peer ranges.** `^1.7.0` on `@scarlett-player/core` and `@scarlett-player/ui` everywhere; a grep across all 17 manifests found no stragglers.
- **Guards and CI.** The three new guards are wired into `ci.yml` after the build, and the artifacts guard also gates `release.yml` before publish with a publish-cannot-be-undone rationale; `upload-cdn.sh` uploads `dist` by glob with an empty-glob failure guard and excludes source maps by pattern shape.
- **Docs.** `docs/architecture.md` is rewritten to the shipped design and dated; no `setup(api)` or `plugin-*` name survives in tracked docs (only a historical changelog version string in `contributing.md`); `plugin-authoring.md` now lives under `docs/` so the core and ui CHANGELOG pointers resolve; the README examples standardise on `createPlayer()` and the audio example starts the first track through the playlist, which is the correct sequence.
- **Changesets.** All 29 are `patch`, consistent with the D4 decision that the whole wave, poster API included, ships as one 1.7.1 patch release under the fixed version group.

## Improvements (none blocking)

1. **`createPlayer()` docblock should name the `player:ready` consequence.** The event docblock says "subscribe before calling `init()` or `load()`", but the documented entry point is `createPlayer()`, which resolves after the emit; a listener attached after awaiting it can never observe the event. That is the accepted D5 trade (the resolved promise is the readiness signal), but only the `PlayerEventMap` docblock hints at it. One sentence in `createPlayer()`'s TSDoc closes the last observable trap of the old shape.
2. **`bigPlayButton` is not plumbed through the embed config.** `UIPluginConfig.bigPlayButton` exists, but `EmbedConfig`, the parser and the embed README never mention it, so every CDN embed gets the button and a host page drawing its own affordance cannot turn it off. A `data-big-play-button="false"` attribute would give the embed parity the D3 config option implies.
3. **The `hls.js` chunk byte-identity invariant is unguarded.** The full and video builds share the `hls.js` chunk name (safe while the two builds emit identical content, which the `chunkFileNames` docblock records was md5-verified by hand on 2026-09-02). `check-embed-chunks.mjs` cannot catch a future divergence: both files would exist and every import would resolve, with the video build's output silently overwriting the full build's. A cheap pin inside the guard: build one variant into a temporary outDir and compare, or assert after the fact that `hls.js` and `hls.light.js` are the only unprefixed chunks.
4. **`hls.js` peer floor sits below the tested version.** `packages/plugins/hls` declares `hls.js: ^1.5.0` as a peer while its devDependencies (and the lockfile, and this wave's tests) use `^1.6.x`. Pre-existing and untouched by this wave; a one-line floor bump belongs in the next changeset batch.
5. **`playbackState` after a paused scrub away from the end.** The tracker (finding 12) records this as deliberately untouched: the hls provider leaves `playbackState` at `'ended'` when a paused viewer scrubs back, and nothing shipped reads that value today. It is the same class of disagreement just fixed for the `ended` key, so it is worth a decision in the next patch wave rather than a wait; the value it should become (`ready`?) needs a deliberate choice, not a drive-by.
6. **`demo/demo.ts` still shows the `new ScarlettPlayer(...)` + `load()` shape.** That shape is now functional (that is the point of D1), but every README points at `createPlayer()`, so the demo is the one place still teaching the old form. Cosmetic, and the demo rebuilds on main anyway.

## Behavior notes (intentional, recorded so nobody rediscovers them the hard way)

- **Plugin-init failures now surface through `load()`.** When auto-init runs inside `load()`, a plugin whose `init()` throws is reported through the load error path (error state, `errorHandler.handle` with `operation: 'load'`) instead of rejecting an explicit `init()` call. Correct for the embed and auto-init shapes, but it is a new way for `load()` to end in a fatal error, and the first consumer debugging a broken plugin will meet it there.
- **`get poster()` reads state, not the element.** For an audio source the element never carries a poster attribute while the state key holds the URL. The docblock says this; consumers who want the element's value should ask the element.
- **Double initialisation is a cheap no-op.** `init()` after `load()`, or a second `init()`, re-runs the pass but initialises nothing (plugins are past `registered`), wires nothing (flag), and re-emits nothing (flag). Verified by reading the guards, not just by the tests.
